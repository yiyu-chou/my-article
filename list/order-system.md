## 一、簡述

此為高一自主學習成果報告書。題目為「班級訂餐管理系統開發」，兩位同學一起合作開發班級訂餐系統，簡化及加速訂餐流程。互相合作與討論，共同學習。

---

## 二、動機

我們學校的午餐採用個人訂餐方式，統一由班級幹部收集大家的訂餐意願及費用，填寫餐單並向餐廳訂餐。而在這個過程中，幹部需一個一個收集大家的資訊，缺乏效率，也容易出錯。我看到了這個問題，於是決定來開發一個班級的訂餐系統，簡化訂餐流程。而剛好班上也有跟我一樣喜歡程式開發的同學，於是我與他討論，並決定一同設計這個系統。

---

## 三、學習目標

- **(一)設計系統UI介面**：學習如何使用 Figma軟體，設計出符合需求的系統介面。
- **(二)學習基礎 React 網頁框架**：學習 React 框架的基本語法，並建構出完整應用程式。
- **(三)運用爬蟲做資料爬取**：學習如何利用網站爬蟲功能解決系統功能需求。
- **(四)學習網站開發流程**：學習多人協作的開發流程與上架部署方式。

---

#### 1. 開發工具

#### 2. 前端架構
React + tailwindcss

![圖五：前端架構 React + tailwindcss](https://yiyu-chou.github.io/my-article/files/order-system/image005.png)

我們的系統是以網頁方式呈現，在前端的架構方面，我們採用 tailwindcss 來裝飾本系統，並使用 React 框架建構系統。而值得一提的是，以前我都是使用原生的HTML、CSS、JavaScript 來建構簡單的應用程式，所以聽到同學跟我介紹這兩個框架時，其實根本不了解這些是什麼，但後來想到，剛好可以藉由這次機會來學習一下，但要從完全不會到成功製作出一個應用程式，其實是不太容易，但當下也沒有想這麼多，就開始上網學習這兩個技術了，所以也花了一些時間在學習新技術方面。透過網路上的文章、Youtube影片以及同學的詢問，邊學邊做，慢慢的做出自己想要的功能。

#### 3. 初探 React

由於我之前有過網頁開發的經驗，對於JavaScript 語言也比較熟悉，所以在 React 技術上就會學的比較快。透過影片及React 官網的學習，我學到了component的概念，useState、useEffect 等基礎函式用法。寫React一陣子之後發現，跟我之前開發網頁的時候也有些差別，以前我都是把HTML、CSS及JS完全分開來寫，但現在是把HTML跟JS寫在一起，也因為使用 tailwindcss， CSS也可以完全寫在HTML標籤裡，讓我感覺比以前方便許多，也感受到React 設計 component的目的。

### (四)測試與修改

功能大概都開發好了後，我們便開始測試。原本以為開發的已經很完美了，距離上線給大家使用已經不遠了，但在測試的過程中，卻出現了許多錯誤，有些還超乎我們的預期。在遇到錯誤的一開始，我們不知所措，甚至一度想逃避問題。後來我們發現，慌亂並不能處理事情，唯有靜下心來找出問題，才能真正解決問題。於是，我們開始依照出錯地方一一解決。

#### 1. 畫面顯示的資訊與API送出的不同
在測試時，我們遇到了一個問題：使用者在畫面選取的餐項與最終發送到後端的餐項不同。這個問題是由於前端程式邏輯錯誤，在一開始沒有把變數規劃好，導致最後錯用變數。經過除錯之後，重寫程式邏輯，來解決這個錯誤。

#### 2. JavaScript 變數型態一直出錯
JavaScript 是一個弱型態語言，所以我們開發時常發生形態上的錯誤，例如：後端傳回來的資料還沒有轉成物件、不小心讓字串比大小、函式傳入或回傳錯型態的變數等。雖然這些看似是小問題，但要在一行行程式裡尋找這些錯誤，有些時候需要花費許多時間，而且有些還可能是潛在的錯誤，我們並未發現。

以上種種都是我們在測試上遇到的問題，事實上所遇到的問題也不止這些。但我們相信，會遇到錯誤是很正常的，而最重要的，就是想盡辦法去解決，從錯誤中學習。

### (五)上線使用

經過測試與修正，功能大致都完善，我們便開始準備上線使用的工作。

#### 1. 部署
我們將前端頁面放置在Github Pages，並透過GitHub Action 功能自動Build，讓我們每次推送程式碼時，都會自動Build 成網頁部署。

![圖八：GitHub Pages 與 GitHub Actions 自動部署示意圖](https://yiyu-chou.github.io/my-article/files/order-system/image008.png)

#### 2. 測試版與實際版
我們在部署方面分為兩部分，一部分為正式使用版，另一個則是測試版，所有程式碼會先到測試版測試，測試完後再Merge 到正式版部署。這樣可先讓新功能到測試版測試，減少直接到正式版而發生錯誤的風險。圖九為示意圖。

![圖九：測試版與實際版部署示意圖](https://yiyu-chou.github.io/my-article/files/order-system/image009.png)

#### 3. 班內使用
部署完後，一開始，我們先於班上測試，讓班上同學使用，過程中，因為較多人使用的緣故，所以也發生了之前測試沒遇到的問題。使用者回報錯誤之後我們也會儘速修復錯誤，讓大家可以正常使用。

**(1)為什麼同學訂餐後管理者介面沒有資料出現**  
訂餐管理者的介面未出現同學的訂餐資料，針對這個問題，我們發現是後端與資料庫連接發生錯誤，導致資料處理錯誤。針對這個問題，在同學回報過後我們立馬修復，讓大家可以使用。

班上使用一陣子之後，我們打算推廣到其他班，讓更多同學使用。於是我們開始準備。我們製作了宣傳海報、更開發了分班功能。圖十為當時製作的宣傳海報。

## 五、問題解決

### (一)硬體資源受限
在開發的初期，我們對於系統架設所需的硬體討論許久，而在預算與安全的考量下，最終選擇將前端頁面放置在GitHub Pages而後端則由另一位同學自建伺服器。

### (二)開發速度偏慢
因為初次使用React 框架，所以對於許多語法陌生，導致開發的進度偏慢。透過不斷的查找資料、相互討論，甚至互相支援，使專案能夠持續進行，並加快速度。

### (三)面臨無頭緒的Bug
在撰寫程式時，時常面臨到自己毫無頭緒的錯誤，而我們透過互相的討論，上網找尋資料，與不斷嘗試，將錯誤修正，並繼續開發下去。

### (四) JavaScript 本身的語言特性
前面說過，因為JavaScript 是弱型態語言，所以很容易出現型態上的錯誤，但我們後來發現這類型的錯誤太頻繁了，導致系統很常出現錯誤，於是我們開始尋找解決辦法。後來另一位同學建議我，要不要把語言從 JavaScript 改變成TypeScript，這樣可以解決這種問題。其實我也沒有學過TypeScript 這個語言，但在另一位同學的說服之下，我們決定來重構這個系統。但這不是說重構就可以重構，因為又是一個新的技術，所以我必須再去學習，我一樣在網路上學習 TypeScript的寫法，也詢問另一位同學，兩人合作漸漸把原本的程式重構。寫了TypeScript 一段時間過後，我也得出了一些心得：我發現使用TypeScript 過後，錯誤率真的變的很低，也因為強型態的原因，VSCode的文字提示都有顯示出來。種種原因使開發的速度真的快很多。多次的錯誤讓我們尋找有沒有更有效的解決辦法，而不是只是針對特定一個小問題作修改，我們認為能夠讓整個系統更穩定，即便花比較多時間，但也是值得的。

## 六、反思與心得

經過這個專案的製作，我覺得我成長了許多，不管是在技術層面還是合作能力上，都增進了不少。學習的速度也比起以前增快許多，也對網站的開發技術更加深入。也許在規劃的一剛開始，會懷疑自己的能力到底能不能完成，遇到問題時可能會很想放棄，但我覺得既然都嘗試了，就要努力把它做好，有很多挫折是正常的，每一次的失敗，都是我們前往成功道路上的力量，在錯誤中學習，才能使自己更加強大。這次的專案，是我目前做過最大的專案，在過程遇到了許多意想不到的事情，也因為這個專案，我學到了很多之前不懂的東西，也學習到如何跟人溝通、解決事情的能力。

在實際做出來專案後，真的有很大的成就感，也產生了很大的感觸：「當你有想法時，就要努力把它實踐出來」、「面對挫折或困難時，只有靜下心來，找錯誤並解決，才能真正的解決問題」。這些也是我學程式以來得到的最大結論。

這次的專案不僅豐富了我的知識，更鍛鍊了我的心志，使我在未來面對挑戰時能夠更加從容、自信。
